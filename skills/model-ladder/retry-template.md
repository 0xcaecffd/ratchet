# model-ladder: the retry dispatch prompt

Fill this in and send it to the rung's agent (`<name>-<rung>-medium`, generated by
`templates/gen_agents.py`). Everything in angle brackets is filled from the task's records;
the standing rules come from the consuming workflow's adapter skill.

> Task `<task_id>`, dir `<task_dir>`, attempt `<k>`, rung `<rung>`, unit `<unit>`.
> First run `ratchet.py resume <task_dir>`, then read `findings.md` and `work.jsonl` in
> full.
> Units verified `self` or `parent` are done: cite them by work line, never regenerate them.
> Units marked `wrong` must be redone and are not inputs.
> Attempt `<k-1>` (`<rung-1>`) ended with class `<X>`, shape `<shape>`; do not repeat that
> shape.
> Append findings under `## A<k>` with `ratchet.py find` as you learn them, and a
> `work.jsonl` line per finished unit, naming its outputs and the control you ran.
> Purpose: `<what this feeds>`.
> `<the adapter's standing rules: where content must stay, what the reply may carry, what is
> never done without the user's approval>`
>
> Reply with: the work lines you added; the finding ids you added, with their status; what is
> still open; any denied call or stopped response.

## What makes a retry useful

- **A different shape.** Name the failed shape and say what to do instead (smaller steps, a
  different tool, a narrower unit). A retry that repeats the shape wastes a rung.
- **A smaller unit.** If one unit failed twice, split it; each part starts at rung 1.
- **No rework.** Verified units are inputs by reference. If the retry regenerates them, the
  records were not read — fix the prompt, not the model.
- **An honest stop.** The agent records the class and shape and stops. The parent climbs; the
  agent never re-dispatches itself.

## Keep dispatch prompts short

Measured 2026-10-04/05: most class (b) stops on the parent itself came while it wrote long
dispatch prompts that narrated sample-analysis work in detail (cord/research
ledger/events.jsonl, session 41f2bd2a). Short prompts that point at files never stopped.

- Put the detail in files the worker reads: the plan, the runbook skill, the task dir's
  `findings.md` and `work.jsonl`. The prompt names the task, the unit, the files to read, the
  scope and the reply format, and nothing more.
- To continue or retry work an agent already has context for, resume that agent with a short
  message (SendMessage) instead of writing a fresh prompt that restates everything.
- If a dispatch is stopped mid-write, check whether an agent started on the truncated prompt
  and stop it before anything else.
